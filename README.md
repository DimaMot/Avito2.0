# Avito Microservices — Платформа аренды вещей

Это микросервисное Java-приложение (аналог Авито) для публикации объявлений, бронирования вещей в аренду и добавления комментариев (отзывов). Проект переписан из монолита, разделен на независимые модули и спроектирован по принципам **SOLID**.

---

## Технологический стек

* **Java & Spring:** Java 21, Spring Boot 3.3.2, Spring Data JPA.
* **Микросервисы (Spring Cloud):** Eureka Server, Config Server, API Gateway, OpenFeign.
* **Базы данных:** PostgreSQL 16 (у каждого сервиса своя изолированная БД в Docker).
* **Тесты и утилиты:** JUnit 5, Mockito, MapStruct, Lombok.

---

## Архитектура системы

Каждый сервис полностью автономен и работает со своей базой данных. Они общаются друг с другом по сети через REST-запросы (OpenFeign).

### Что интересного сделано в коде:
* **Борьба с N+1 в сети:** При выгрузке списков вещи или бронирования не спамят сеть кучей мелких запросов. Данные скачиваются одной быстрой пачкой (Batching) и склеиваются в памяти за время O(1).
* **Порядок в коде (SOLID):** Вместо огромных цепочек `if-else` при обновлении полей или фильтрации статусов используется гибкий паттерн **«Стратегия»** и полиморфный реестр.
* **Распределенное удаление:** Если удалить пользователя из `user-server`, он автоматически по сети сотрет все свои объявления в `item-server`, чтобы в базе не оставалось «мусора».

## Описание REST API (Единая точка входа: порт 8080)

Все запросы отправляются через шлюз API Gateway на порт **8080**. Для работы с вещами и бронированиями в заголовках запроса необходимо передавать ID пользователя: `X-Avito-User-Id`.

### Пользователи (`avito-user`)
* `POST /users` — создать пользователя
* `GET /users/{id}` — получить пользователя по ID
* `PATCH /users/{id}` — обновить имя/email пользователя
* `DELETE /users/{id}` — удалить пользователя (удаляет и его вещи)

### Вещи и отзывы (`avito-item`)
* `POST /items` — добавить вещь в каталог
* `GET /items/{id}` — посмотреть карточку вещи (владелец видит даты аренды, покупатель — нет)
* `PATCH /items/{id}` — обновить параметры вещи
* `GET /items/search?text=...` — поиск вещей по названию или описанию
* `POST /items/{id}/comment` — оставить отзыв к вещи (только для тех, кто реально брал её в аренду)

### Бронирования (`avito-booking`)
* `POST /bookings` — забронировать вещь на определенные даты
* `PATCH /bookings/{id}?approved=true` — подтвердить или отклонить бронь (только для владельца вещи)
* `GET /bookings/{id}` — посмотреть детали бронирования
* `GET /bookings?state=...` — получить историю своих бронирований (фильтры: `ALL`, `FUTURE`, `PAST`, `CURRENT`)

## Быстрый запуск в Docker

Сборка образов настроена на слоях (**Spring Boot Layertools**).

1. **Скомпилировать проект на компьютере:**
   mvn clean package -DskipTests
   
2. **Запустить всё в Docker Compose одной командой:**
   
   docker compose up --build -d
   
   *Система сама дождется готовности баз данных, включит Config Server, Eureka, Шлюз и запустит все приложения.*

## 🧪 Тестирование

Бизнес-логика проекта покрыта **изолированными юнит-тестами на Mockito**. Тесты написаны на чистом `MockitoExtension` без поднятия Spring-контекста, благодаря чему выполняются мгновенно. Они проверяют:
* Все позитивные и негативные сценарии работы сервисов (обработка ошибок 404, валидация дат).
* Симуляцию сетевых ошибок (`FeignException.NotFound`).
* Правильность работы SOLID-стратегий обновления полей.

## План развития проекта (Roadmap)

Проект планируется активно развивать дальше. В ближайших планах:
1. **Интеграционные тесты:** Покрытие сквозных сценариев с использованием **Testcontainers** для запуска реальной базы PostgreSQL в тестах.
2. **Сервис запросов на предметы:** Создание нового модуля, где пользователи смогут оставлять заявки на нужные вещи, которых пока нет в каталоге, с автоматическим уведомлением при их появлении.
3. **Сервис статистики на Apache Kafka:** Переход на асинхронную архитектуру. При бронировании или добавлении отзывов сервисы будут отправлять события в Kafka, а новый сервис статистики будет собирать аналитику популярности вещей.
