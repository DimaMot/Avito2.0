# Avito Microservices — Платформа аренды вещей

Это микросервисное Java-приложение (аналог Авито) для публикации объявлений, бронирования вещей в аренду и добавления
комментариев (отзывов). Проект переписан из монолита и разделен на независимые модули.

---

## Технологический стек

* **Java & Spring:** Java 21, Spring Boot 3.3.2, Spring Data JPA, Spring Kafka.
* **Микросервисы (Spring Cloud):** Eureka Server, Config Server, API Gateway, OpenFeign.
* **Базы данных:** PostgreSQL 16 (у каждого сервиса своя изолированная БД в Docker).
* **Тесты и утилиты:** JUnit 5, Mockito, MapStruct, Lombok, Testcontainers.

---

## Архитектура системы

Каждый сервис полностью автономен и работает со своей базой данных. Они общаются друг с другом по сети через
REST-запросы (OpenFeign).

```
                           ┌────────────────────────┐
                           │   Postman / Frontend   │
                           └───────────┬────────────┘
                                       │ (порт 8080)
                                       ▼
                       ┌───────────────────────────────┐
                       │   Spring Cloud API Gateway    │
                       └───────────────┬───────────────┘
                                       │ (lb://)
         ┌─────────────────────────────┼─────────────────────────────┐
         ▼ (порт 8081)                 ▼ (порт 8082)                 ▼ (порт 8083)
┌──────────────────┐          ┌──────────────────┐          ┌──────────────────┐
│   avito-user     │          │   avito-item     │          │  avito-booking   │
│  (user-server)   │          │  (item-server)   │          │ (booking-server) │
└────────┬─────────┘          └────────┬─────────┘          └────────┬─────────┘
         ▼                             ▼                             ▼
   [usersDB:5432]                [itemsDB:5433]               [bookingsDB:5434]
```

### Что интересного сделано в коде:

* **Борьба с N+1 в сети:** При выгрузке списков вещи или бронирования не спамят сеть кучей мелких запросов. Данные
  скачиваются одной быстрой пачкой и склеиваются в памяти за время O(1).
* **Порядок в коде:** Вместо огромных цепочек `if-else` при обновлении полей или фильтрации статусов
  используется гибкий паттерн **«Стратегия»** и полиморфный реестр.
* **Распределенное удаление:** Если удалить пользователя из `user-server`, он автоматически по сети сотрет все свои
  объявления в `item-server`, чтобы в базе не оставалось «мусора».

## Описание REST API (Единая точка входа: порт 8080)

Все запросы отправляются через шлюз API Gateway на порт **8080**. Для работы с вещами и бронированиями в заголовках
запроса необходимо передавать ID пользователя: `X-Avito-User-Id`.

### Пользователи (`avito-user`)

* `POST /users` — создать пользователя
* `GET /users/{id}` — получить пользователя по ID
* `PATCH /users/{id}` — обновить имя/email пользователя
* `DELETE /users/{id}` — удалить пользователя (удаляет и его вещи)

### Вещи и отзывы (`avito-item`)

* `POST /items` — добавить вещь в каталог
* `GET /items/{id}` — посмотреть карточку вещи (владелец видит даты аренды, покупатель — нет)
* `PATCH /items/{id}` — обновить параметры вещи
* `GET /items/search?text=...` — поиск вещей по названию или описанию
* `POST /items/{id}/comment` — оставить отзыв к вещи (только для тех, кто реально брал её в аренду)

### Бронирования (`avito-booking`)

* `POST /bookings` — забронировать вещь на определенные даты
* `PATCH /bookings/{id}?approved=true` — подтвердить или отклонить бронь (только для владельца вещи)
* `GET /bookings/{id}` — посмотреть детали бронирования
* `GET /bookings?state=...` — получить историю своих бронирований (фильтры: `ALL`, `FUTURE`, `PAST`, `CURRENT`)

## Быстрый запуск в Docker

Сборка образов настроена на слоях (**Spring Boot Layertools**).

1. **Скомпилировать проект на компьютере:**
   mvn clean package -DskipTests

2. **Запустить всё в Docker Compose одной командой:**

   docker compose up --build -d

   *Система сама дождется готовности баз данных, включит Config Server, Eureka, Шлюз и запустит все приложения.*

## Тестирование и Надежность системы

Проект укомплектован двухуровневым слоем автоматического тестирования.

* **Изолированные Unit-тесты сервисов (JUnit 5 + Mockito):** Написаны на чистом `MockitoExtension` без поднятия Spring-контекста, благодаря чему выполняются мгновенно. Проверяют позитивные и негативные сценарии (валидация дат, симуляция сетевых ошибок `FeignException.NotFound`).
* **Сквозные интеграционные тесты (Testcontainers + MockMvc):Во время сборки Maven автоматически поднимается реальная база данных **PostgreSQL 16 в изолированном Docker-контейнере** с помощью Testcontainers.
    * Тесты сервисов изолированно проверяют транзакционную логику работы с СУБД.
    * Веб-тесты контроллеров через `MockMvc` проверяют сквозной проход данных от HTTP-заголовков (`X-Avito-User-Id`) и сериализации Jackson до физических инсертов в базу данных, а также верифицируют работу глобального обработчика ошибок `ExceptionController`.
    * Для предотвращения эффекта транзакционного кэша (Hibernate First-Level Cache) в тестах применяется принудительный сброс сессии через `EntityManager` (`flush` / `clear`), гарантируя честные SQL-запросы к СУБД в докере.

## План развития проекта (Roadmap)

Проект активно развивается в сторону Event-Driven (событийной) продакшен-архитектуры. Ближайшие цели:

1. **Микросервис `avito-request`** — автономный доменный модуль заявок на предметы, которых нет в каталоге, с автоуведомлением арендаторов при публикации подходящего товара.
2. **Смена БД сервиса аналитики** — MongoDB или ClickHouse.
3. **Testcontainers в CI/CD** — перенос запуска контейнеров БД в GitHub Actions.
4. **Кеширование на Redis** — снижение нагрузки на БД и ускорение API.
